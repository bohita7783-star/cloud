## 2. 前提：設備台帳Next（ユーザー提供の資料から。会社の実データはここに書かない）

- 会社サーバー上の Excel/VBA。データは **設備台帳.xlsx／設備履歴.xlsx／設備履歴_拡張.xlsx**、書類は書類フォルダ（修繕工事依頼書・現場異常報告）。
- **運用版**（設備台帳Next_運用版.xlsm）は「確認画面 → 書込み → 読み直して照合 → ログ」の安全策を持つ。ローカル版とサーバー版がある。
- 台帳は **旧PROG（設備台帳PROG.xlsm）・旧Next（設備台帳Next.xlsm）と共用**。
- **履歴は機器名称でひもづく。** 名称を後から変えると、履歴・拡張のキーも直す必要がある。
- **「登録中」の機器**：台帳に1行追加し、分かることだけ入れる（メーカー・型式・製造番号・設置年は推測で入れない）。備考1の先頭に「【登録中】」。名称は最初から最終形にする。
- 2026-11-03 の事故（2024-010 で対象機器11台の登録漏れ・日付誤り）から決まったこと：
  - 根本原因C：**運用版の画面を通らずファイルを直接書き換えた** → 直接書き込みは事故修正に限る。
  - 「分かった分だけ登録して完了に見せない」：不明は**保留**にし、保留が残るものは完了扱いにしない。
  - 推定で確定しない。出典の優先順位（日付＝完工届の完了日＞見積書＞お知らせ・写真）。
  - 台数・日付・機器名の存在を機械的に点検する（`modAudit.bas`、未テスト・未取り込み）。
- OCR の濁点・半濁点の誤読（プーリー→フーリー等）：対策は「台帳・履歴の表記から辞書を作り、濁点を無視して照合。候補が複数なら決めずに確認」。
- 2026-11-03 時点の未完了：サーバー版の運用版ブックの「データフォルダ」「書類フォルダ」設定の更新（フォルダ移動のため）。**連携の前にこれが片付いていること。**

原本の資料（ユーザー提供の2ファイル）は、ダウンロード用ZIPの `設備台帳Next_資料/` に入れてある。社内のパスなどを含むので、**リポジトリには入れていない**。

## 3. 前提：ホームボックス側（すでにあるもの）

- スマホのPWA（Pixel 9a 想定）。データは端末の中だけ（IndexedDB）。圏外でも動く。現在 v0.4.0。
- **設備台帳の正式17項目（固定）**：製造者名、機器番号、製造番号、製造年月日、設置年月日、設置場所、種類と質量、電動機メーカー、電動機出力(kW)、定格電流(A)、圧力タンク容量(L)、口径、揚程(m)、電動機形式、電圧区分、回転数(min⁻¹)、標準耐用年数(年)
- 追加項目（初期値）：型式、系統、定格電圧(V)、風量(m³/min)、点検周期、備考（設定で追加・非表示が可能）
- 設備の基本列：設備ID（EQ-000001 形式、アプリが振る）、設備名、分類、場所の区分、QR
- **台帳CSV**（設定 →「設備台帳CSV」）
  - 1行目が見出し：`設備ID, 設備名, 分類, 場所の区分, QR, 17項目, 追加項目`（`HB-LEDGER-TEMPLATE.csv` 参照）
  - UTF-8（BOM付き）・Shift_JIS を読める。書き出しは UTF-8（BOM付き）・CRLF。Excel の数式とみなされる先頭文字（= + - @）は無害化して書き出す。
  - 取り込んだ値は「**未確認**」になる（現物・銘板で確かめて「確認済」にする）。
  - 安全策：見出しの重複、知らない列、非表示にした項目の列があると、**読み飛ばさずに止める**。
  - 更新は**設備IDが一致する行だけ**。設備IDが空の行は新規扱い（← 連携では問題になる。5章）。
  - 分類は決まった9種類（ポンプ、ファン・送風機、発電機、ボイラー・熱源、空調機、電気設備、給排水、消防・防災、その他）。それ以外は「その他」。
- 写真・点検記録・異常案件を設備ごとに持つ。異常案件から会社様式の現場異常報告Excelを端末で作れる（承認済みひな形が必要）。
- 決定事項（HANDOVER.md 5章）：**台帳の正本は会社の台帳**。ホームボックスは現場用の写しと確認結果の候補。自動の双方向同期はしない。業務データを外部へ送らない。

## 4. 連携の設計

```
            ┌──────────── 会社PC（会社サーバー） ────────────┐
            │  設備台帳Next 運用版                            │
            │   台帳・履歴・拡張（正本）   書類フォルダ        │
            └────┬─────────────────────────────▲────────────┘
     ① 台帳CSV（読むだけ）│                    │② 取り込み候補CSV＋写真・報告書
        Next→HB          │                    │   運用版の確認画面から取り込む
                         ▼                    │   （直接書き込まない）
            ┌──────────── スマホ（ホームボックス） ───────────┐
            │  設備の写し（未確認）・写真・点検・異常案件・報告書 │
            └─────────────────────────────────────────────────┘
     ③ 用語辞書（台帳・履歴の表記）… Next→HB。入力候補・銘板の読み取り候補に使う
```

### 第1段階：台帳 → ホームボックス（読むだけ。最初にやる）

- Next 側：運用版に「ホームボックス用CSVを書き出す」を作る（または既存の書き出しを使う）。列は `HB-LEDGER-TEMPLATE.csv` に合わせる。
  - 設備名 ← 機器名称（**Next のひもづけキーと同じ文字列**）
  - 17項目 ← 対応する列（Q1・Q2 の答えで対応表を確定）
  - 備考 ← 備考1（「【登録中】」はそのまま。ホームボックスでも登録中と分かる）
  - 設備ID は空欄でよい（下のホームボックス側の変更が前提）
- ホームボックス側の変更（このリポジトリで行う）：
  1. **台帳キー**（Next の機器名称）を設備に持たせ、CSVの再取り込みは台帳キーで一致させる（今は設備IDだけで一致させているため、2回目の取り込みで重複が増える）。
  2. 取り込み結果に「新規・更新・変わらない・CSVに無くなった機器」の件数を出す。CSVに無くなった機器は消さずに「台帳に無い」と表示する。
  3. 取り込み元（例：「設備台帳Next 2026-11-07 書き出し」）を出典として記録する。
- 合格条件：架空の台帳CSV（`sample_ledger_next_to_homebox.csv`）を2回取り込んでも重複しない／値は「未確認」／【登録中】が見える／知らない列で止まる。

### 第2段階：ホームボックス → 台帳（候補として渡す）

- ホームボックス側：「台帳への取り込み候補」を書き出す（`sample_candidates_homebox_to_next_DRAFT.csv` は**案**。列はQ1の答えで確定する）。
  - 種別：点検／異常／新規機器
  - 機器名称（台帳キー）、日付、内容、測定値、担当、出典、写真ファイル名、報告書ファイル名、保留理由、確認状態
  - 写真と報告書Excelは同じZIPに入れる（書類フォルダへ置くのは人の操作）。
- Next 側：運用版に「候補を取り込む」画面を作る。**必ず確認画面を通し、書込み → 読み直して照合 → ログ**。
  - 台帳に無い機器名称 → 自動で作らない。「登録中」として追加するかを人が選ぶ。
  - 保留理由のある行 → 取り込まず保留一覧に残す（完了扱いにしない）。
  - 日付は候補の日付をそのまま使い、推定しない。
- 合格条件：架空データで、確認画面を経ずに書き込まれる経路が無い／保留が一覧に残る／取り込み後に `modAudit` 相当の点検で警告なし。

### 第3段階：用語辞書

- Next の台帳・履歴・拡張にある機器名・部品名から辞書を作り、ホームボックスに渡す（読むだけ）。
- ホームボックスでは入力候補・銘板写真の読み取り候補に使う。濁点を無視して照合し、候補が複数なら決めずに確認を求める。**型式・製造番号・金額は補正しない。**

## 5. 分かっている課題・リスク

| 課題 | 対応 |
|---|---|
| ホームボックスのCSV取り込みは設備IDでしか一致させない | 第1段階で台帳キー（機器名称）での一致を追加する |
| Next の機器名称は後から変えると履歴が切れる | 名称は最初から最終形（Next の決まり）。ホームボックスは名称を変えない（台帳キーは読み取り専用にする） |
| 台帳は旧PROG・旧Nextと共用 | 取り込みは運用版だけ。旧側に「登録中」が見えることは了承済み（Next の決まり） |
| 列の対応が未確認 | Q1・Q2 の答えまで、列の対応表は仮 |
| スマホと会社PCの受け渡し | Q5 の答え次第。外部クラウドは使わない |
| Next 側の作業はこの環境からできない | Next のブックを開ける側（会社PC・別チャット）で作業する |
| サーバー版の設定更新が未完了（2章） | 連携の前に片付ける |

## 6. 守ること（両方の決定事項から）

1. 台帳の正本は Next。ホームボックスは写しと候補。**自動の双方向同期はしない。**
2. Next への書き込みは**運用版の確認画面だけ**。ファイルの直接書き換えは事故修正に限り、事前にバックアップ。
3. 分からないことは推定で埋めない。**保留**にして人に聞く。保留が残るものは完了扱いにしない。
4. 黙って読み飛ばさない（知らない列・重複・非表示の項目があれば止める）。
5. 業務データを外部へ送らない。開発・試験は**架空データだけ**。会社の実データ・社内のパスをリポジトリに入れない。
6. 型式・製造番号・金額は自動で補正しない。
