## `hb-report-package/2` で増えたもの（HomeBox 0.3.0 ／ 変換ツール 2.5.0〜）

`case` に報告書の欄を追加（どれも空欄 `null` 可）：

| 項目 | 様式の欄 |
|---|---|
| `報告の段階` | AB2（`（第１報）` `（第２報）` `（第３報）` `（最終）` `(事故報告)`。空なら第１報） |
| `部署` `ビル名` `報告者` `報告者の役職` | AP2・AP3・AP4・BC4（設定の報告者情報から自動入力） |
| `当事者` `当事者の区分` `連絡先` | G7・S7・AG7 |
| `現場確認の実施者` `現場確認の内容` | L8・AP8（AC8） |
| `一次対応の実施者` `一次対応の内容` | L9・AP9（AC9） |
| `処置報告の区分` `処置の実施者` `処置の確認者` | G32（`応急処置：` `恒久処置：` `観察中：`）・AR32・AR34 |

最上位に `contacts`（通報・現状報告、20件まで）：

```json
"contacts": [
  {"区分": "オーナー・テナント", "手段": "メール", "相手": "架空", "所属": "架空不動産株式会社"},
  {"区分": "社内", "手段": "電話", "相手": "架空課長", "所属": null}
]
```

- `区分`：`関係機関`（3枠）／`オーナー・テナント`（4枠、相手に「　様」が付く）／`対応業者`（2枠）／`社内`（2枠）。枠を超えたら変換停止。
- `手段`：`電話` `メール` `FAX` `訪問` など。様式には `【電話】` `【ﾒｰﾙ】` の形で入る。
- `/1` のパッケージに `/2` の項目が入っていたら停止。
- 対応・処置内容は 15〜27 行、1行51字で折り返す。入りきらない時は停止し「続報に分けて」と案内する（アプリの「様式に入るか確認」で事前に分かる）。

## 規則

| 項目 | 規則 |
|---|---|
| 項目名 | `field_survey_report.yaml` の変数名と同じ日本語。変換ツールは同じ処理で扱う |
| 日時 | ISO 8601、時差つき（`+09:00`）。変換ツールは日本時間に換算 |
| 時刻 | `HH:MM` |
| 真偽値 | JSON の `true` / `false` |
| 空欄 | `null` |
| 写真 | 3枚まで（現行様式の枠）。`元写真` は `photos/` 直下 |
| 写真の照合値 | `sha256` は**必須**（小文字16進64桁）。撮影時に記録し、書き出し時と変換時に画像から計算し直して照合 |
| 写真名 | `案件ID_設備ID_連番_種別.拡張子` または、案件の外で撮った写真は `PHYYYYMMDD_設備ID_連番_種別.拡張子`。**名前の設備IDは案件の `設備ID` と一致すること** |
| 設備のない案件 | `設備ID` が `null` の案件には写真を入れない（写真は必ず設備に結び付ける） |
| 撮影日時 | `撮影日時` に加えて、その根拠 `撮影日時の根拠`（`EXIF`／`ファイル日時`／`登録時刻`）と、アプリに取り込んだ `登録日時` を入れる（v0.1.1〜） |
| 対応経過 | 8件まで（パッケージとしては50件を超えたら停止） |
| 余分なもの | 案件に使わない写真や、`package.json` と `photos/` 以外のファイルは入れない（入っていたら変換停止） |
| 知らない項目 | **最上位・`app`・`case`・`equipment`・写真・対応経過のどの階層でも**変換停止（項目名の打ち間違いで値が黙って消えるのを防ぐ） |
| 許可する最上位項目 | `schema`, `created_at`, `app`（`name`, `version`）, `case`, `equipment`（`id`, `name`, `category`, `location`）, `photos`, `timeline`, `contacts`（/2のみ） |

## 版の組み合わせ

| ホームボックス | 変換ツール |
|---|---|
| v0.1.0 | v2.4.0〜（v2.4.2 では sha256 必須・写真名の規則を満たすので変換できる） |
| v0.1.1 / v0.1.2 | **v2.4.2〜**（v0.1.2では台帳表示順だけ変更し、パッケージ形式は変えない） |
| v0.3.0（/2） | **v2.5.0〜**（承認済み一覧は engine-2.5.0 で再署名が必要） |

## 版の上げ方

- 項目を足すときは `hb-report-package/2` にし、変換ツール側の `homebox_adapter.py` を同時に更新する。
- 報告書に印字する欄を増やす場合は、変換エンジンの変更範囲（`engine_policy.py`）も変わるので、ひな形の**再承認が必要**。


## 台帳項目定義との分離（HomeBox v0.1.3）

設備台帳の項目定義は `hb-ledger-fields/1` のJSONで独立して管理する（項目名・単位・グループ・順番・非表示・内部キー）。これを編集しても、既存の報告書パッケージ `hb-report-package/1` の構造は変更されない。会社様式への変換は引き続きv2.4.2以降を用いる。

**この項目定義JSONは、会社が承認するExcelひな形の署名・承認一覧とは別物。** ひな形の承認を省略する目的には使えない。
