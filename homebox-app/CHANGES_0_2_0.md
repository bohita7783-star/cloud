# HomeBox v0.2.0 — この端末で会社様式のExcelを作る（2026-11-07）

Termux を使わず、ホームボックスの中で会社様式のExcelを作れるようにした。

## しくみ

- 変換ツール v2.4.2 の Python ファイルを**そのまま**（1バイトも変えずに）`engine/` に置き、Pyodide（ブラウザで動く Python）で動かす。
  - Termux版と同じ変換処理・同じ承認検査（電子署名、原本ハッシュ、部品ごとの検査）を通る。
  - `tests/check_engine_sync.py` で、変換ツールのリリースと同一であることを確認できる。
- Pyodide と必要な部品（lxml・Pillow・cryptography など、約19MB）は `pyodide/0.27.7/` に同梱。外部のCDNからは読み込まない。
- 変換は Web Worker（別スレッド）で行うので、画面は固まらない。
- 承認者の公開鍵一覧 `trusted_approvers.json` は、アプリと一緒に配信する（Termux版と同じ考え方。初期状態は鍵なし＝何も承認されていない）。

## 使い方

1. 設定 →「会社様式（承認済みひな形）」で、管理者から受け取った空白ひな形（.xlsx）と承認済み一覧（.approved.json）を選び、「照合して登録する」。
2. 異常案件 →「報告書にする」→「この端末で会社様式のExcelを作る」。
3. ダウンロードに Excel ができる。変換ログ（JSON）も保存できる。会社PCで内容と印刷を確認してから提出する。

「報告書パッケージを書き出す（Termuxで変換する場合）」も残している。

## 速さ（目標：1分以内）

| 場面 | このテスト環境での実測 | スマホでの目安 |
|---|---|---|
| 初めての準備（19MBの取得＋起動）、10 Mbit/s | 12秒 | 20〜25秒 |
| 初めての準備、5 Mbit/s | 22秒 | 30〜35秒 |
| 2回目以降の起動（キャッシュから）＋変換 | 3秒 | 10〜15秒 |
| 準備済みの状態での変換 | 0.4秒 | 1〜2秒 |

- スマホでの目安は、CPUを4倍・8倍遅くした実測（変換まで13秒・27秒）からの推定。**Pixel 9a での実測はまだ。**
- 案件画面を開いた時点で、裏で準備を始める（入力している間に終わる）。
- 会社様式を登録した時点で部品の取得と保存が終わるので、現場（圏外）では2回目以降の速さになる。設定の「Excel作成の準備」でも事前に済ませられる。
- Pyodide は版ごとの別キャッシュに入れるので、アプリを更新しても再取得しない。

## 検証（Chromium、架空データ）

- `tests/e2e_excel.js`：改ざんした承認一覧は登録を拒否 → 正しい承認一覧で登録 → 案件からExcelを作成（件名・写真・EMFの保持を確認）→ **機内モードで再読み込みして再作成** → 未登録時は案内を表示。すべて合格、画面のエラー0件。
- 作成したExcelの変換ログ：承認ID、入力の種類（homebox-package）、変更禁止部品11個のバイト一致を記録。
- 既存の `e2e_app.js`（11段階）・`e2e_schema.js`・単体テストもすべて合格。
