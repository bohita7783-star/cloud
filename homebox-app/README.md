# ホームボックス v0.4.0（会社の空様式で、報告書と同じ書き方のExcelを作る）

> **v0.4.0：** 登録した様式の版を確かめ（報告書の枠・写真枠を読み取る）、写真を消した空様式の写真枠に写真を貼る。設定と案件画面に、様式の種類・写真枠の数・承認者を表示。変換エンジン 2.6.0。承認済み一覧は再署名が必要。詳しくは [CHANGES_0_4_0.md](CHANGES_0_4_0.md)。

> **v0.3.0：** 実際の現場異常速報と同じ欄・同じ書き方で出力（報告の段階、通報・現状報告、時系列の折り返し、原因・処置報告）。「様式に入るか確認」「続報を作る」、報告者情報といつもの連絡先。変換エンジン 2.5.0。承認済み一覧は再署名が必要。詳しくは [CHANGES_0_3_0.md](CHANGES_0_3_0.md)。

> **v0.2.0：** 案件画面の「この端末で会社様式のExcelを作る」で、Termuxを使わずにExcelを作成。変換ツール v2.4.2 と同じ処理・同じ承認検査をアプリ内（Pyodide）で実行。詳しくは [CHANGES_0_2_0.md](CHANGES_0_2_0.md)。

設備台帳（会社の台帳と同じ正式17項目は固定。追加項目は追加・削除・並び替えが可能）・写真・点検記録・異常案件を設備ごとに管理し、会社様式の報告書用パッケージを書き出すオフラインアプリ（PWA）。

- データはこの端末のブラウザの中だけ。業務データを外部へ送る処理はない。アプリを開いたときに、更新確認のため配信元へ接続する。
- 台帳の正本は会社の台帳。ここは現場用の写しと確認結果の候補。
- デザインは `homebox-lp/`（LP v0.1.1）を基準にしている。
- 全体構成・受け入れ条件は [ARCHITECTURE.md](ARCHITECTURE.md)、変換ツールとの受け渡し形式は [DATA_CONTRACT.md](DATA_CONTRACT.md)。
- 会社様式のExcelは、設定で承認済みひな形を登録すれば**アプリ内で作れる**（v0.2.0）。Termuxで変換する場合は変換ツール v2.6.0 以降。

## Pixel で使う

1. このフォルダーを、**ホームボックス専用のオリジン**で HTTPS 配信する（このリポジトリのGitHub Pagesは架空データの試験用）。
2. Pixel の Chrome で開き、メニュー →「ホーム画面に追加」。
3. 設定 →「消されにくい設定」を有効にする。
4. 設定 →「空のCSVひな形」で台帳の形を確認し、会社台帳を CSV で取り込む（取り込んだ値は「未確認」）。
5. 「撮る」で設備を選んで撮影 → 異常案件で写真を選び、説明を書いて「報告書パッケージを書き出す」。
6. 設定 →「会社様式（承認済みひな形）」でひな形と承認済み一覧を登録（1回だけ。Wi-Fiのある場所で）。
7. 案件の「この端末で会社様式のExcelを作る」→ ダウンロードに Excel。（Termuxを使う場合は「報告書パッケージを書き出す」→ `run_homebox.sh`）

## できること

| 画面 | 内容 |
|---|---|
| ホーム | 設備の横断検索、最近の写真、対応中の案件 |
| 設備台帳 | 分類・場所でまとめた一覧。初期の正式17項目と追加項目（型式・系統・定格電圧・風量・点検周期・備考）を表示。正式17項目は固定。追加項目は設定から追加・名称変更・移動・非表示・復元が可能。値ごとに確認状況（確認済／未確認／対象外）と出典。写真、点検記録、関連案件 |
| 撮る | 設備を選ぶ → 種別を選ぶ → 撮影。原本のまま保存し、`案件ID_設備ID_連番_種別.jpg` の規則で命名。撮影日時はEXIF→ファイル日時→登録時刻の順で採り、根拠と登録日時を別に残す |
| 異常案件 | Field Survey と同じ項目、写真3枚の選択と説明、対応経過8件、書き出し前の検査（別の設備の写真・同じ画像の重複・説明なしなど） |
| 設定 | バックアップ／復元（全件を検査してから、まとめて置き換え）、台帳CSVの書き出し・取り込み（UTF-8・Shift_JIS）、項目設定JSONの書き出し・取り込み、全削除 |

## 制限

- 17項目の並び順は、2026-11-06付「HomeBox用17項目テンプレート.md」と照合済み。保存キーは変更せず、表示順のみ修正（v0.1.2）。
- 写真は端末の容量を使う。定期的にバックアップを書き出し、復元できるかも試すこと。
- 報告書は写真3枚・対応経過8件まで（現行様式の枠）。
- Pixel 9a の実機での動作確認はまだ（撮影写真がギャラリーに残らないか、圏外での動作など。ARCHITECTURE.md の受け入れ条件）。

## v0.1.3 — 17項目を固定せず、項目を自由に増減

初回起動時は正式な17項目＋追加6項目が用意されています。項目定義は端末内 IndexedDB の `meta.ledger_fields_v1` に保存します。v0.1.2 から更新した既存データは同じ保存キーで読み取るため、移行のために台帳を作り直す必要はありません。

> **v0.1.4 から：** 正式17項目は固定（非表示・改名・並べ替え不可）。以下の操作は**追加項目**に対して行います。v0.1.3 で正式17項目を変更していた端末は、起動時に会社の台帳どおりに戻ります（値は残ります）。

1. **項目追加**：設定 → 設備台帳の項目を編集 →「＋ 項目を追加」。項目名・単位・根拠／規程を登録（必ず追加項目に入ります）。
2. **名称変更**：「編集」から変更。過去の入力値は不変の項目キーで保存されるため消えません。旧項目名はCSV取込時の別名として保管。
3. **並べ替え**：「↑」「↓」で同じ分類の中を移動。会社台帳の列順を変えた場合も対応。
4. **削除**：「削除」は**非表示・保管**。過去の値・確認状況・出典は消えず、「復元」で再表示。業務台帳の履歴を守るため、完全削除は実装しません。
5. **別端末への共有**：「項目設定JSONを書き出す」で設定だけを保存し、別端末で「項目設定JSONを取り込む」。設備情報・写真・案件は変更しません。端末にのみ存在する項目は非表示で残し、重複・矛盾した項目名があれば取り込み拒否します。
6. **CSV**：CSVは表示中の項目だけを書き出します。非表示にした項目に入っていた値は通常CSVには出ませんが、バックアップZIPには残ります。CSV取込で不明な列・非表示の列は黙って捨てず停止します。

追加項目は最大100件（基本・追加・非表示を含めた総数）。根拠欄は「社内要領」「省令名・条文」等の参照メモであり、適用可否の自動判定ではありません。項目を法令上の義務として採用する場合、内容・施行日・適用設備は会社の責任者が別途確認してください。

**注意**：項目定義は端末内の設定であり、複数端末で自動同期しません。項目定義の配布・改訂承認と、会社台帳正本への反映は会社側の管理手順が必要です。登録済み業務データを用いた移行、Pixel 9a実機でのオフライン撮影、会社様式Excelでの印刷は未検証です。
