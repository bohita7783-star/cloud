# 会社様式ひな形の承認手順書（管理者向け）

対象：Field Survey 変換ツール 2.3.3-approval-preview 以降（2.6.0 で「2-1 空様式の作り方」を追加）
位置づけ：**検証版**。正式な会社承認と、Windows版Excelでの表示・印刷検証が終わるまで、業務提出には使わない。

---

## 0. この仕組みで守っていること

| 守ること | しくみ |
|---|---|
| 原本を変えない | 変換ツールは原本を読むだけ。出力は常に別ファイル |
| 承認していない様式では動かない | 管理者の秘密鍵で署名された「承認済み一覧」がないと停止 |
| 承認後に原本がすり替わったら止まる | 原本全体と、全部品のSHA-256を承認時と照合 |
| 外部リンク・数式・EMF・チェックボックス・補助シートを勝手に消さない | これらは「変更禁止」。出力でもバイト単位で同一であることを検査 |
| 変換ツールが想定外のところを書き換えたら止まる | 変更してよい部品・セルはコード（engine_policy.py）に固定。出力を独立に再検査 |
| 過去の案件の文字が残らない | 消去するセルの旧内容、作成者名などが出力に残っていたら停止 |
| JSONの書き換えで承認を偽装できない | 承認はEd25519の電子署名。1文字でも変えると署名が合わなくなる |

### 役割

| 役割 | 担当 | 持つもの |
|---|---|---|
| 承認者 | 様式の管理責任者（例：所長・情報システム部門が指名した人） | 秘密鍵（承認者のPCだけ。パスフレーズで暗号化） |
| 公開鍵一覧の管理者 | 変換ツールの配布担当 | `trusted_approvers.json`（公開鍵だけ） |
| 現場の利用者 | 報告書を作る人 | 承認済み一覧と原本（スマホ）。鍵は持たない |

承認者と現場の利用者は、**別の人**にすること。

---

## 1. 準備（初回だけ）

1. 承認者のPCに Python 3.10以上を入れ、`pip install cryptography lxml` を実行する。
2. 承認者がPCで鍵を作る。
   ```
   python approval_sign.py keygen --name "承認者の氏名" --out C:\承認鍵
   ```
   - `approver_private_key.pem`：**秘密鍵**。パスフレーズ（12文字以上）で暗号化される。PCの外へ出さない。スマホ・共有フォルダー・メールには絶対に置かない。
   - `approver_public_entry.json`：公開鍵。配布担当へ渡す。
3. 配布担当は、`approver_public_entry.json` の中身を `trusted_approvers.json` の `keys` に追加し、**新しい版のパッケージとして配布**する。スマホ上で直接編集しない。

---

## 2. 空白のひな形を作る（会社PC・Excel）

1. 現行の様式ファイルを**コピー**する。元のファイルは触らない。
2. コピーで、過去の案件の記入内容・写真を消す。
3. 次の削除は、**業務上の必要性を確認してから**行う。自動では行わない。
   - コメント、記入例シート、非表示シート
   - 外部リンクの解除：解除すると、その数式は現在の値に置き換わる。必要なリンクは残してよい（承認すれば保持される）。
   - 「ドキュメント検査」：消した情報は元に戻せない。必ずコピーで行う。
4. 保存したファイルを `blank_template.xlsx` とする。

### 2-1. 空様式の作り方（2.6.0〜、現場異常速報）

元にするのは **2026-10-17／10-31 と同じ配置の様式**（報告書1枚＋写真3枠）。古い配置（行が多い、写真の列が違うなど）は、検査で「枠の位置が違います」と出て承認できない。

| 消すもの | Excelでの操作 | 消さないと |
|---|---|---|
| 写真（セルの中に入れた写真） | 写真のセル（B5・B24・B43）を選び Delete | 「セル内画像」で承認できない |
| 写真（浮いている写真）と赤丸・矢印・文字枠 | 写真シートで各図形をクリック → Delete（ホーム → 検索と選択 → オブジェクトの選択 で囲むと楽） | 「写真が残っています」「図形が残っています」で承認できない |
| 写真シートの件名・日付・番号・説明 | B1、P3、P5・P24・P43、説明の各行を Delete | 前の案件の文字が残る（出力時に消されるが、原本に残る） |
| 報告書シートの記入内容 | 入力欄を Delete（数式・プルダウンの一覧は消さない） | 同上 |

- 写真の枠（結合セル）・罫線・列幅・行の高さは**変えない**。変換ツールは写真枠の位置を結合セルから読み取る。
- 写真は変換ツールが写真枠の上に貼る（浮いている図として。セル内画像にはしない：Excel 365 以外や LibreOffice、スマホのビューアでも写真が見え、赤丸を上に描けるため）。
- 検査報告の「様式と写真の入れ方」に、読み取った写真枠（例：B5:L21、番号 P5、説明 N7・N10・N13・N16・N19）が出る。Excelの写真シートと見比べて合っているか確認する。

## 3. 検査する

```
python template_inspector.py blank_template.xlsx --out C:\承認作業\2026-11
```

できるもの：
- `inspection_report.md`：検査報告。セルの値・コメント本文・外部リンクの参照先は表示しない。
- `approval_manifest.pending.json`：承認候補。**この時点では承認ではない。**

報告の先頭に「承認できない理由」があれば、ひな形を直して検査し直す。

---

## 4. Excelで中身を確認する（承認者）

検査報告の「人が確認すべきもの」を、Excelで1つずつ確認する。

| 確認項目 | 確認場所 | 見ること |
|---|---|---|
| 全シート | シート見出しを右クリック → 再表示 | 非表示シートを含め、過去の案件・個人名がないか |
| コメント | 校閲 → すべてのコメントを表示 | 不要なら削除し、検査からやり直す |
| 外部リンク | データ → リンクの編集 | 参照先が業務上必要か。参照先のパスに個人名などがないか |
| 名前の定義 | 数式 → 名前の管理 | 外部ブックを参照していないか |
| 図・画像・EMF | 各シート | 過去の現場写真が残っていないか（記入例シートのセル内画像も） |
| 写真枠 | 検査報告「様式と写真の入れ方」 | 読み取った写真枠・番号・説明の位置が、写真シートの欄と合っているか |
| チェックボックス | 開発 → デザインモード | 初期状態が正しいか |
| 文書情報 | ファイル → 情報 → プロパティ | 作成者などは出力側で空にするが、原本も確認 |
| 入力欄以外のセル | 各シート | 過去の案件の文字が、消去対象外のセルにないか |

確認した日付、確認者、確認した項目を、社内の記録（紙または台帳）に残す。

## 5. 署名する（承認者のPCだけ）

```
python approval_sign.py sign ^
  --template blank_template.xlsx ^
  --pending C:\承認作業\2026-11\approval_manifest.pending.json ^
  --key C:\承認鍵\approver_private_key.pem ^
  --approver "承認者の氏名" ^
  --i-reviewed-in-excel ^
  --valid-days 365 ^
  --out C:\承認作業\2026-11\approvals
```

- `--i-reviewed-in-excel` がないと署名しない。
- 署名の直前にひな形をもう一度検査する。検査後に1バイトでも変わっていれば署名しない。
- できるもの：`approvals\<原本のSHA-256>.approved.json`。読み取り専用で保存される。
- 承認ID（`APV-日付-乱数`）を社内の記録に書き写す。

---

## 6. 配布する

スマホの変換ツールのフォルダーに、次の2つを置く。

```
FS_Phone_Converter_v2_3_3/
  company_template.xlsx              ← 承認した blank_template.xlsx（名前だけ変更可、中身は変えない）
  approvals/<原本SHA-256>.approved.json
  trusted_approvers.json             ← 配布担当が配った版のまま
```

ファイル名を変えても、中身のSHA-256で照合するので問題ない。中身を1バイトでも変えると停止する。

## 7. 実行時に止まる場合と対処

| 停止メッセージ（APPROVAL STOP: …） | 原因 | 対処 |
|---|---|---|
| このひな形の承認済み一覧がありません | 承認していない、または原本が変わった | 原本を承認済みのものに戻す。変更が必要なら2章から再承認 |
| 承認候補（未承認）の一覧です | pendingのまま置いた | 5章の署名をする |
| 署名が一致しません | 承認済み一覧が編集された | 承認者が署名した元のファイルに戻す |
| 登録されていない承認者の鍵 / 失効した鍵 | 公開鍵一覧にない | 配布担当に確認 |
| 承認された原本と違うファイル | 別のひな形の一覧を使っている | 正しい組み合わせにする |
| 変換ツールの変更範囲が承認時から変わっています | 変換ツールを更新した | 新しい版で3〜5章をやり直す |
| 有効期限が切れています | `--valid-days` を過ぎた | 2〜5章で再承認 |
| 変更禁止の部品が変わりました / 承認されていない部品が追加 | 変換ツールの異常 | **出力を使わない**。版とログを添えて報告 |
| 許可されていないセルが変わりました | 変換ツールの異常 | 同上 |
| 過去の案件の文字列が出力に残っています | 消去対象外のセルに旧内容がある、など | ひな形を見直して再承認 |

**停止したら、手作業で報告書を作る**（従来の手順）。停止を回避するためにファイルを編集しない。

---

## 8. 変更・失効

- **様式を変える**：新しいひな形として2〜5章をやり直す。古い承認済み一覧は `approvals/` から外す。
- **承認者が替わる・鍵を紛失した**：配布担当が `trusted_approvers.json` の該当鍵を `"revoked": true` にし、新しい版を配布する。その鍵で署名した承認は全部無効になるので、新しい承認者が再署名する。
- **変換ツールを更新する**：変更範囲の版（`engine_policy_version`）が変わると、既存の承認は無効になる。更新後に再承認する。

---

## 9. この仕組みでは防げないこと

- スマホ上で変換ツールのプログラムや `trusted_approvers.json` を書き換えられると、検査自体を外せる。各変換ログに、プログラムと公開鍵一覧のSHA-256を記録している。配布した版の値と照合して検出する。
- 承認者がExcelでの確認を誤れば、その内容はそのまま承認される。検査報告は確認の補助であり、DLP（情報漏えい防止の専用製品）ではない。
- 図形の中の文字、変更禁止のシートの中身は、承認時の人の確認に依存する。
- Windows版Excelでの表示・再計算・印刷の再現性は、別途確認が必要。
- スマホ側のクラウド同期・バックアップによる外部送信は、端末の設定で別途止める。
